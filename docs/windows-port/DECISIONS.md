# Decisions

Choices made during the unattended Windows port (TASK.md §7). Architecture-level choices have an ADR in `adr/`; this
log records every choice, small or large, with the reason. Newest last.

| ID | Date | Milestone | Decision | Reason |
| --- | --- | --- | --- | --- |
| D-001 | 2026-10-16 | M0 | Architecture: Swift Support+Core on Windows, WPF shell, engine and shell talk over the engine's stdio (ADR-001). | Spike: Core and its tests compile on Windows without touching business logic. |
| D-002 | 2026-10-16 | M0 | UI: WPF on **.NET 10** instead of the brief's .NET 8 (ADR-002). | .NET 8 support ends 2026-11-10, within weeks; .NET 10 is the current LTS (to 2028-11) and is what the machine and `windows-latest` carry. |
| D-003 | 2026-10-16 | M0 | SQLite: the system `winsqlite3.dll` exposed as module `SQLite3` (ADR-003). | No vendored source; `import SQLite3` unchanged in seven files; JSON functions present (3.51.1). |
| D-004 | 2026-10-16 | M0 | SHA-256/SHA-1: portable Swift implementation in AgentHUDSupport, CryptoKit-named shim only where CryptoKit is missing (ADR-004). | Deterministic ids; testable against CryptoKit on macOS; no dependency. |
| D-005 | 2026-10-16 | M0 | Shell↔engine transport is the engine's standard input/output, not a named pipe `\\.\pipe\agenthud-<SID>-ui`. | Anonymous pipes inherited by one child cannot be opened by another process (no squatting, no DACL to get wrong) and tie the engine's life to the shell's (ADR-001). Hooks and `--mcp` still use named pipes. |
| D-006 | 2026-10-16 | M0 | Platform seam at **file granularity**: a macOS file in `System/` (and `CodexDesktopIPC`) stays where it is, untouched, and is excluded from the Windows build in `Package.swift`; a Windows file of the same API lives in `Sources/AgentHUDCore/Platform/Windows/`. Shared files get `#if os(Windows)` only around single statements or functions. | Zero diff in the macOS implementations, so upstream changes to them rebase cleanly; moving them into `Platform/Darwin/` (TASK.md M3 wording) would rename the files upstream keeps editing. |
| D-007 | 2026-10-16 | M0 | Windows builds run from an ASCII path. Locally the repository lives at `E:\桌面项目\agent-hud-open`; builds go through the junction `E:\src\ahud` with `--scratch-path E:\src\ahud-build`; `scripts/build-windows.ps1` will create such a junction itself when the tree's path is not ASCII. | Swift 6.4.1's clang driver fails to link a test DLL whose response files live under a non-ASCII path (the error text is lost too); the same tree links through an ASCII junction. |
| D-008 | 2026-10-16 | M0 | Folders: data `%APPDATA%\Agent HUD Open` (TASK.md §3), lock `%LOCALAPPDATA%\app.agenthud\instance.lock`; both from the environment variable first, then `SHGetKnownFolderPath`. Foundation's `urls(for:)` is not used on Windows. | Foundation maps Application Support to `%LOCALAPPDATA%` and Caches to `%TEMP%` on Windows and traps when an override points at a missing folder; environment variables let tests use temporary folders. |
| D-009 | 2026-10-16 | M0 | Instance lock on Windows: the lock file held open for writing with `FILE_SHARE_READ` only (released by the system at exit or crash), holding `<executable path>\n<pid>`. No named mutex. `runningApplication(at:)` reads the file sharing everything and checks the pid still runs that executable. | The share mode is the Windows equivalent of `flock`; a mutex would be a second, possibly disagreeing source of truth; reading never blocks a starting copy. |
| D-010 | 2026-10-16 | M0 | Hook/MCP channels: named pipe `\\.\pipe\agenthud-<SID>-<24 hex of SHA-256 of the lower-cased socket path>`, message mode, DACL `O:<SID>D:P(A;;GA;;;<SID>)`, `PIPE_REJECT_REMOTE_CLIENTS`, first instance with `FILE_FLAG_FIRST_PIPE_INSTANCE`; clients open with `SECURITY_SQOS_PRESENT|SECURITY_IDENTIFICATION` and talk only to a server process running as their own SID. | Keeps "only the user can reach it", "one process serves a path" and "a request is one message" (architecture.md) without file-system sockets; defends against pipe-name squatting by another user. |
| D-011 | 2026-10-16 | M0 | Child processes: `CreateProcessW` with the executable path and an MSVCRT-quoted command line; only the three standard handles inherited (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`); `CREATE_NO_WINDOW`; each child in its own job object; `.bat`/`.cmd` refused. `stop()` closes stdin, then after the 2 s grace terminates the job. | No shell string is ever built (G7); a batch file can only run through `cmd.exe`, whose parsing re-opens command injection (CVE-2024-24576 class); Windows has no SIGTERM. |
| D-012 | 2026-10-16 | M0 | `ps` and `lsof`: on Windows `ProviderCommand.run` answers the two fixed invocations Core makes (`/bin/ps -U … -o pid=,command=` and `/usr/sbin/lsof … -p <pid> -iTCP -sTCP:LISTEN -Fn`) from Toolhelp + `NtQueryInformationProcess` and `GetExtendedTcpTable`, in those tools' output format, current user's processes only, backslashes written as `/`. | The readers and their tests (which inject that output) stay unchanged; no external program is run. |
| D-013 | 2026-10-16 | M0 | `getuid()` exists on Windows and returns `UInt32.max`, which no file owner equals (the CRT reports owner 0). | Lets shared code that only *names* a user compile; any ownership check fails closed instead of passing. |
| D-014 | 2026-10-16 | M0 | Provider HTTP on Windows uses WinHTTP (`WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`, never a proxy for loopback), no redirects, no cookies, no WinHTTP auth, self-signed certificates accepted for `127.0.0.1` only; module `CWinHTTP` (system library, Windows only). | swift-corelibs URLSession lacks `bytes(for:)` and server-trust handling, and libcurl ignores the system proxy that macOS's URLSession follows. |
| D-015 | 2026-10-16 | M0 | Features without a documented Windows mechanism are compiled out behind their API and reported as unsupported: Codex Desktop IPC, the Codex daemon control socket, terminal/session jump (iTerm2), DeepSeek Harness process liveness. | TASK.md §7.2: never guess. |
| D-016 | 2026-10-16 | M0 | Transcript following in the permission hook polls the record every 250 ms on Windows. | No vnode events for an open handle on Windows; the read is incremental. |
| D-017 | 2026-10-16 | M0 | Sub-agents: `.claude/agents/port-reviewer.md` and `port-tester.md` are committed; this session runs from outside the repository, so it invokes them as general-purpose agents given the definition's text as their brief (read-only reviewer, no-source-edit tester). | The agent registry is read from the session's working directory at start. |
